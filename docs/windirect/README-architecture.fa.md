این پچ فقط بازآرایی ساختار است و روی برنچ `feature/windirect-foundation` در commit زیر ساخته شده:

```text
4421a5502bcfce72e55098fc57c8dd24e2a586fa
```

هیچ commit یا push به مخزن گیت‌هاب انجام نشده است. فایل‌های پچ قبلی اشتراک را دوباره اعمال نکنید؛ این پچ روی نسخه‌ای است که آن تغییرات را قبلاً دارد.

## اعمال پچ

در ریشه پروژه و روی برنچ مربوط:

```powershell
git branch --show-current
git apply --check windirect-apps-refactor.patch
git apply windirect-apps-refactor.patch
python manage.py migrate
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test windirect payment
```

اگر مرحله check خطا داد، ادامه ندهید؛ خروجی را بررسی کنید. این مرحله هیچ تغییری ایجاد نمی‌کند. برای انتقال، دیتابیس یا migrationهای قبلی را پاک نکنید؛ migrate معمولی کافی است. اگر تغییر محلی دیگری دارید، پیش از اعمال آن را ثبت یا پشتیبان‌گیری کنید.

| مسیر | برچسب Django | مسئولیت |
| --- | --- | --- |
| windirect/connections | windirect_connections | مدل و فرم اتصال اینستاگرام، ثبت اتصال و قطع یا فعال‌سازی آن |

| windirect/direct | windirect_direct | قوانین دایرکت، رویداد پیام، مسیریابی پاسخ و صفحات شبیه‌سازی و لاگ |

هر شش مورد، اپ واقعی و جداگانه Django با AppConfig و migration مستقل هستند؛ فقط پوشه‌بندی فایل‌ها یا import مجدد مدل‌های اپ قبلی نیستند. برچسب‌ها پیشوند دارند تا با اپ‌های دیگر مثل accounts تداخل نداشته باشند. نام صحیح بخش اتصالات `connections` است.

در هر اپ، مدل‌ها در models.py، فرم‌ها در forms.py، مدیریت در admin.py و مسیرها در urls.py قرار گرفته‌اند. inlineهای ادمین در فایل inline_admin.py همان اپ قرار دارند. منطق کسب‌وکار در services.py نگه‌داری می‌شود. خروجی اکسل و فیلتر پاسخ‌نامه‌ها در exports.py و queries.py اپ فرم قرار دارند.

## پوشه مادر

`windirect` نام مجموعه باقی می‌ماند. ریشه آن دیگر فایل‌های features_models.py، features_views.py، features_forms.py، features_admin.py، direct_services.py و subscription_models.py ندارد.

- apps.py: ورودی مجموعه و حفظ تاریخچه اپ قبلی.
- urls.py: تجمیع مسیرهای شش اپ با namespace عمومی فعلی.
- views/dashboard.py: نمای تجمیعی داشبورد.
- common/: مدل انتزاعی ابزار، پایه فرم و ادمین، تطبیق متن، داده مشترک پنل و سازوکار مشترک CRUD ابزارها؛ بدون مدل واقعی دیتابیس و بدون اپ مستقل.
- tests/: آزمون‌های یکپارچه پنل، ارتباط قابلیت‌ها و انتقال migration.
- migrations/: تاریخچه قدیمی و migration انتقال؛ وجود این پوشه ضروری است.

منطق عمومی ویرایش، فهرست، حذف و فعال‌سازی ابزارها در common/assets.py مشترک است تا سه اپ آن را کپی نکنند. مسیر هر ابزار متعلق به اپ خودش است و فقط نوع مجاز همان اپ را می‌پذیرد. کنترل حق استفاده در اشتراک می‌ماند؛ مدیریت خود اتصال در اپ connections است.

منطق پرسش و پاسخ فرم و تهیه کارت ویترین در اپ‌های خودشان است. موتور دایرکت مسئول دریافت و مسیریابی پیام به این سرویس‌هاست. تطبیق متن مشترک، به مدل اپ کامنت وابسته نیست.

## قالب‌ها و ظاهر

HTML و کلاس‌های استایل بازطراحی نشده‌اند. بیس و تم فعلی حفظ شده‌اند و مسیر قالب‌ها مرتب شده است:

- templates/windirect/connections/
- templates/windirect/comments/
- templates/windirect/direct/

- templates/windirect/subscriptions/
- templates/windirect/common/assets/ برای قالب‌های عمومی ویترین، فرم و قانون دایرکت.

قالب پایه، داشبورد و partialهای عمومی در محل مشترک مانده‌اند. قالب‌های ویترین از قالب‌های عمومی ابزار استفاده می‌کنند؛ HTML مشابه جداگانه ایجاد نشده است. برچسب قالب اشتراک از اپ subscriptions بارگذاری می‌شود و نام فعلی آن حفظ شده است. راهنماهای قبلی هم به docs/windirect منتقل شده‌اند.

## سازگاری مسیرها و ادمین

namespace عمومی `windirect` و URL صفحات فعلی حفظ شده‌اند؛ لینک‌های سایت نیاز به تغییر ندارند. مثلاً مسیر ابزار همچنان `/windirect/panel/tools/forms/` است.

در ادمین شش بخش با عنوان فارسی و تنظیمات Daisy فعلی نمایش داده می‌شوند. آدرس ادمین مدل‌ها با app_label جدید تغییر می‌کند؛ مثلاً:

```text
/admin/windirect_connections/instagramconnection/
/admin/windirect_comments/automation/
/admin/windirect_subscriptions/subscriptionplan/
```

اگر اسکریپت یا کد خارج از این برنچ دارید، import مدل‌ها را از اپ مالک انجام دهید:

```python
from windirect.connections.models import InstagramConnection
from windirect.comments.models import Automation
from windirect.forms.models import ConversationForm
from windirect.subscriptions.models import SubscriptionPlan
```

رشته مجوز مدل نیز با برچسب جدید نوشته می‌شود؛ مثلاً `windirect_comments.change_automation`. مجوزهای ذخیره‌شده کاربران و گروه‌ها هنگام migration با حفظ شناسه منتقل می‌شوند. importهای داخلی موجود در برنچ اصلاح شده‌اند؛ ماژول تجمیعی windirect.models برای پنهان کردن ساختار قدیمی باقی نمانده است.

## دیتابیس و migration

این کار همچنان از همان پایگاه داده پروژه استفاده می‌کند. جدا بودن اپ‌ها به معنی جدا کردن دیتابیس نیست.

۱۹ مدل بین شش اپ تقسیم شده‌اند؛ جدول‌های قبلی با نام‌های `windirect_*` حفظ شده‌اند. این تصمیم عمدی است: جابه‌جایی مالکیت مدل در Django، نیازمند بازسازی جدول، کپی داده یا تغییر شناسه‌ها نیست. نام جدول نشان‌دهنده مسیر پایتون مدل نیست.

migrationهای اولیه اپ‌های جدید، مدل‌ها را فقط در state ثبت می‌کنند. migration پرداخت، ارتباط فاکتور و تلاش پرداخت با مدل سفارش اپ اشتراک را در state اصلاح می‌کند. migration 0005 اپ مادر مدل‌های قدیمی را از state خارج می‌کند، بدون حذف جدول. ContentType قبلی با همان شناسه به app_label جدید منتقل می‌شود؛ مجوزها و ارتباط کاربر/گروه حفظ می‌شوند.

در نصب از صفر نیز تاریخچه قدیمی ابتدا جدول‌ها را می‌سازد و سپس انتقال انجام می‌شود. بنابراین فایل‌های migration قبلی باید در مخزن بمانند. در تاریخچه این برنچ، دو migration هم‌نام شماره 0012 پرداخت قبلاً ادغام شده بودند؛ migration جدید پس از migration ادغام 0013 قرار دارد و state انتخاب‌های تراکنش را با مدل فعلی هماهنگ می‌کند.

اگر نوع محتوای تکراری در دیتابیس دست‌کاری‌شده وجود داشته باشد، migration با پیام مشخص متوقف می‌شود تا مجوزهای متصل به شناسه دیگری بدون بررسی حذف نشوند. مسیر استاندارد نصب و انتقال در تست بررسی شده است.

## پرداخت و قابلیت‌ها

فاکتور، زرین‌پال، کیف پول، تراکنش، CommissionSplit و تسویه سهم‌ها همچنان در payment هستند. فقط ارجاع آن‌ها به سفارش اشتراک به اپ جدید اصلاح شده است. مدل‌ها و روابط سایر خدمات منتقل نشده‌اند.

قیمت‌گذاری، تخفیف، مالیات، تمدید، ارتقا، هدیه و امکانات پلن بازطراحی نشده‌اند. این مرحله اتصال واقعی متا یا قابلیت جدید اضافه نمی‌کند. مقدار SECRET_KEY و DEBUG تغییر نکرده است.

## آزمون‌ها

در بررسی نهایی، ۹۷ تست پروژه موفق شدند؛ بررسی سیستم و makemigrations --check --dry-run نیز بدون خطا بود. پچ روی کپی تازه همان commit با git apply بررسی و اعمال شد.

آزمون‌های موجود این برنچ، صفحات پنل، کامنت و دایرکت، فرم، ویترین، اکسل، اشتراک و پرداخت را پس از بازآرایی بررسی می‌کنند. تست‌های اضافی مالکیت واقعی مدل‌ها، حفظ مسیر عمومی و انتقال داده از ساختار قبلی را بررسی می‌کنند.

در آزمون انتقال، اتصال، قانون، رویداد، اجرا، پلن، دوره خرید، سفارش و فاکتور از مدل‌های تاریخی ساخته می‌شوند؛ پس از migration، شناسه‌ها، روابط، جدول‌ها، ContentType و مجوز گروه و کاربر بررسی می‌شوند. تست‌های migration نیز برای نصب از صفر اجرا می‌شوند.

پیش از استقرار روی دیتابیس واقعی، پشتیبان‌گیری انجام دهید. اجرای درگاه بیرونی واقعی و بررسی بصری مرورگر جزو این بازآرایی نبوده‌اند.
